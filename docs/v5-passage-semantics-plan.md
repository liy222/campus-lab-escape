# SP-01 门锁与门禁通行语义修正计划

状态：用户已选择方向A；通行语义与追加动态贴图修复均完成有限自动验证，待真人验收；实际执行及限制见evidence/project/stages/v5-passage-semantics/reviews/delivery.md。代码基线b09908b。原画风/主题按用户本次反馈认可；该认可不涵盖通行逻辑、所有主题或整体版本。

## 为什么修

用户反馈：“为什么打开前厅储物柜锁才能进器材准备台，正常逻辑不是打开门锁吗，画风主题倒是合格了，”。当前GeneratedRules.exits按本区域全部谜题完成开放下一通道；生成命名合同只说明code/sequence/circuit/item，没有把装置的物理用途与通行效果对应起来。前端出口按钮也没有使用公开unlocked禁用或显示锁态。因此既能数学上通关，又可能表现为开柜子直接开放另一房间。

本次产品选择原话：“门锁或门禁控制通行，柜子只负责线索和物品（推荐）”。选择方向是实施依据，不是新版本试玩接受；原体验反馈见human-reviews/v5-handpainted-rebuild/round-02/review.md。

## 怎么做

1. Host根据真实前置拓扑推导用途。每房唯一末题的祖先必须覆盖本房其余题，才作为门禁控制装置；目的地来自真实下一房间或EXIT，不凭名字、数组位置或ID猜测。
2. 在生成outline加入真实effect：passage_control控制哪条通路；当前骨架没有柜体玩法，实际effect仅passage_control/puzzle_control，unlocks_material_slots只记录真实物品/资料释放事实；本次不实现material_container或额外柜内取物流程，也不允许柜锁身份冒充现有载体。
3. 新生成名称按用途及现有terminal/circuit等载体准入，门禁不能被命名成储物柜锁；没有实际容器效果的装置不能冒充柜锁。合法AI原名保留，坏结果直接拒绝，不改原稿、不重试。Host说明写真实门禁效果与目的地，不泄答案。
4. 前端复用已有exits.unlocked：锁时禁用并显示“已锁定”，解锁后显示“可通行”，移动前再核当前公开状态；服务器继续掌握真正通行权限。保留目的地、键盘可访问名称与HP-01修复。
5. 保留当前受认可的画风、素材及原谜题数量/机械依赖。优先使用已有门禁终端、供电箱等可表达载体，不新增取钥匙步骤、柜子功能、房间或新主题包。
