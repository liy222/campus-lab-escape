# v3.4 全流程剧透与 AI 伙伴准备参考

> 内部完整剧透，供设计、调试和未来 AI 伙伴行为设计参考。对应 `level_version=3.4.0`、`schema_version=1.4.0`，呈现层为 v4.2。这里描述当前规则，不代表本文件已接入游戏或作为模型提示词使用。请勿把整份剧透直接放进模型上下文。

## 玩法边界

游戏有 R1 实验准备室、R2 设备实验室、R3 出口控制室，最后到 EXIT。房间不是唯一线性的：普通门闩可以提前拉开，玩家能先去别的房间观察、再返回；但供电、电脑数据读取、道具取得、纸条插入、终检和出口状态仍由各自前置条件控制。成功打开的普通门会保持开放。

对每件重要设备，先观察才会出现可用操作。数字锁接受密码后还要单独开柜；电路通过检查后还要单独合总闸；电脑启动两次、登录后还要再读一次记录；出口刷卡后还要显式启动终检。通过终检仍需释放门锁、推门，再走出出口。

本参考包含服务端规则真值，不能把真值、完整路线或本文件全文发送给 AI。玩家知识只应按实际观察到的线索、拿到的物件和已看到的公开状态判断；服务端接受某操作不代表玩家已发现其理由。

## R1：实验准备室

### 观察与推理

观察墙钟得到实验开始时间 **21:17**；观察实验记录得知样本索引前两位取样本编号、后两位取实验开始时间的分钟数。先观察并拿起样本玻片，将玻片放到显微镜上，再次观察显微镜，才读到样本编号 **42**。因此储物柜的四位索引是将 **42** 与 **17** 拼接成 **4217**。门边铭牌 `LAB-42` 是实验室编号线索，不是柜码前两位的来源；4217 的前两位来自显微镜看到的样本编号。

### 操作与状态

观察储物柜后提交 `4217`，柜锁进入已接受状态但柜门仍关闭；再点击“拉开柜门”（`interact`）才会打开，重复观察不会开柜。观察柜内保险丝并拿取。柜内旧标签给出批次源序 **▲ ● ■ ★**，记住或稍后返回查看。普通的 R1 设备间门闩可观察后提前拉开并往返，不要求先完成所有可选观察。

### 可选故事

拿走保险丝后，柜底会显露凹槽；观察可发现旧合照及背面的交接留言。这是隐藏故事线索，不是通关条件，也不提供必须的谜题答案。

## R2：设备实验室

### 电源箱：准备、接线、供电

观察电源箱，然后依次打开箱盖、移开护板。安装从 R1 取得的保险丝后，3×3 线路盘才可操作。旋转盘面模块并提交“检查线路”；服务器按起点到终点之间相邻模块端口是否互相朝向来判断连通。通过后状态是 `CIRCUIT_READY`，总闸仍未合上；再操作电源箱合上总闸，才到 `POWER_ON` 并供电。

线路盘可能有多种可行接法，不存在需要照抄的唯一旋转数组。以下是一种从新局全模块初始角度开始、按顺时针点击的可行示例；中心格不在这条通路上，也不必接入。其他有效接法同样可以通过。若从已有存档继续，应按当前端口方向判断，不要照搬从零开始的点击次数。

| 行 | c0 | c1 | c2 |
|---|---|---|---|
| 上 | `c00: 1次 / EW` | `c01: 1次 / EW` | `c02: 2次 / SW` |
| 中 | `c10: 2次 / SW` | `c11: 0次 / NS`（不需接入） | `c12: 0次 / NS` |
| 下 | `c20: 0次 / NE` | `c21: 1次 / EW` | `c22: 3次 / NW` |

其中一条连通路径为 `c00 → c01 → c02 → c12 → c22 → c21 → c20 → c10`，起点 `c00` 与终点 `c10` 的外侧接口均朝西。这里的次数只适用于全新、全零旋转的盘面；判定依据是端口互惠连通，而不是模块都转到某个固定方向。该例来自本任务的纯内存领域路线验证证据 `evidence/documentation/gameplay-walkthrough-20261018/verification.json`，不是 UI/API 或真人测试。

保险丝安装后会消耗，不能从背包取回。

### 电脑与托盘

供电后观察电脑，第一次操作启动，第二次操作完成启动并显示登录界面。维护说明要求 `USER` 使用完整实验室编号，`PASS` 使用实验开始时间的 `HHMM` 格式、不含冒号。组合 R1 铭牌与维护说明得到 `USER=LAB-42`；组合钟面 21:17 与格式说明得到 `PASS=2117`。

登录成功后电脑只是 `UNLOCKED`；还要再次操作电脑读取封存记录，才到 `DATA_READ`，托盘中的研究纸条和门禁卡此时才显露。分别观察并拿起两件物品。纸条给出读取位置 **第3、第1、第4、第2位**，并带有四格定位孔；门禁卡保留在背包中，供 R3 出口使用。

观察箱背维护签是可选故事。它只在供电后显露，记录历次交接留言；不影响线路、登录、门或通关。

R2 控制室门闩也可提前拉开，不要求先读取电脑或拿齐托盘物品；如果提前去了 R3，仍需回到 R2 取得后续所需物品并完成状态前置。

## R3：出口控制室

### 插入纸条与提前准备

观察终检控制台，再将研究纸条插入纸槽。纸条插入后会显露四个设备按钮和可编辑的顺序草稿；这一步可以早于刷出口门卡和启动终检。此时可先根据线索推理或填写草稿，但提交仍会被拒绝，直到门卡已接受且玩家显式启动终检。未提交的顺序草稿属于前端临时输入，不是服务器通关状态。

### 推出设备顺序

查看 R1 柜内旧标签，源序是 **▲ ● ■ ★**。研究纸条指定按第 **3、1、4、2** 位读取，所以转录为 **■ ▲ ★ ●**。观察 R3 设备对应表：**■=通风，▲=冷却，★=照明，●=安全**。因此玩家按序操作 **通风 → 冷却 → 照明 → 安全**。

这会得到设备顺序（内部标识）`ventilation, cooling, lighting, safety`。图形与设备对应关系、源序和读取位置来自三个不同房间的线索，不能只靠房间内一张表推出完整答案。

### 终检与离开

观察出口门并用门禁卡，出口到 `CARD_ACCEPTED`。回到已插纸的终检控制台，在当前面板上显式按“启动终检”按钮；按钮位于设备顺序区域，但推进的是出口状态到 `FINAL_CHECK`。现在才可提交四设备顺序。正确提交会设置终检完成，但出口仍未解锁。然后到出口门操作“释放门锁”（`UNLOCKED`）、“推开出口”（`OPEN`），最后移动到 `EXIT` 才算通关。只通过终检或只打开门都不等于已经离开。

## 轻量目标依赖表

| 目标 | 玩家需要的证据/物件 | 关键操作与服务器前置 | 成功后的公开结果 |
|---|---|---|---|
| 打开 R1 储物柜 | 解题时可组合记录规则、钟面分钟、显微镜样本编号；规则并不要求先发现这些线索 | 观察柜、提交正确密码、再开柜；显微镜读数需要先放入玻片再观察 | 柜开；柜内保险丝和源序标签可见 |
| 恢复 R2 供电 | R1 保险丝；装保险丝后公开的 3×3 盘几何 | 开盖、移护板、装保险丝、旋转、提交连通检查、再合总闸 | `POWER_ON` |
| 读取电脑记录 | 解题时可组合 R1 实验室编号、钟面时间、R2 维护格式；猜中字段也可通过校验 | 两次启动、登录、再操作读取记录 | 托盘显露纸条与门卡 |
| 准备 R3 终检 | 研究纸条、R1 源序、R3 设备表、门禁卡 | 插纸；刷卡到 `CARD_ACCEPTED`；显式启动到 `FINAL_CHECK` | 终检可提交；插纸后可先显按钮/起草 |
| 完成并离开 | 转录顺序 | 提交四设备顺序；释放门锁、推门、移动到 EXIT | `check_done`、出口 `OPEN`、`won` |

这张表区分推理解题依据与服务器硬前置。线索帮助玩家推出密码或顺序，但柜码、登录字段和终检顺序校验并不要求先收集每一条对应线索：猜中正确答案也可能通过。服务器硬前置来自当前状态，例如目标已观察、对象当前可见、持有并安装所需物品、设备阶段正确，以及终检必须在门卡接受并显式启动后提交。普通门可提前打开，玩家也可先去后续房间观察再返回；功能推进仍受保险丝、供电、电脑记录、托盘物品和终检阶段约束。这不是唯一房间顺序。

## 玩家知识与后台真值

| 信息 | 玩家何时能知道 | 后台/判定真值边界 |
|---|---|---|
| 样本编号 42 | 玻片放到显微镜并再次观察后 | `4217` 是服务端柜锁答案；铭牌 `LAB-42` 不构成它的样本编号证据 |
| 柜码 4217 | 玩家分别发现记录规则、21:17、样本标记后可推导 | 服务端只在提交时精确校验，不因玩家推理正确自动开柜 |
| 登录字段 | 发现铭牌、钟面和 R2 维护说明后可组合推导 | 服务端校验 `LAB-42` 与 `2117`；电脑还要依次经过启动、登录、读记录 |
| 线路盘解法 | 保险丝安装后可见当前 3×3 几何；可逐格观察端口关系 | 后台只检查公开起点/终点及邻格互惠端口连通；不要求唯一角度数组 |
| 终检顺序 | 发现源序、纸条读取位置和设备对应表后可推导 | 后台只在 `FINAL_CHECK` 阶段校验已提交的四设备序列；草稿和推理不改变通关状态 |
| 两条故事线索 | 保险丝取走后观察柜底凹槽；供电后观察箱背签 | 隐藏发现仅计入可选故事/统计；不是核心谜题前置 |

AI 伙伴若要帮助玩家，应根据该玩家已经看见的线索和当前公开状态说话。它不能把后台答案、尚未发现的线索、全流程顺序或其他隐藏状态当作玩家已知事实；正式游戏状态仍由服务器动作判定。

## 未来 AI 伙伴的引导建议（尚非本文件所定义的已接入功能）

以下是可以用于后续设计评审的引导方式示例，不表示已经新增或接入这些对话、目标追踪或主动提示功能。应先问玩家目前观察到了什么，再给一个小问题或单步方向；让玩家自己操作、确认和提交。

| 卡点 | 可问的问题/轻提示示例 | 逐步增强方向 |
|---|---|---|
| R1 柜码 | “记录里说索引的后两位来自哪里？你已经看到钟面停在几点了吗？” | 引导分别找样本编号与分钟数，再让玩家自己拼接；不要一上来报完整柜码 |
| 显微镜读数 | “玻片现在是否已经放进载物台？放好后再观察一次会看到什么？” | 指向先取玻片、使用玻片、再次观察的动作顺序 |
| R2 登录 | “维护说明里的 USER 要完整到什么程度？PASS 的格式要不要保留冒号？” | 引导把铭牌与维护说明、钟面与 HHMM 规则分别对应；让玩家自己输入 |
| 线路盘 | “起点的外侧接口朝哪边？相邻两格需要怎样才能接通？” | 引导看起点/终点和相邻端口，再让玩家逐段检查；不给固定旋转次数或假定唯一解 |
| 纸条转录 | “源序的第3位是什么？它在设备表里对应哪台设备？” | 先提示一个位置，再鼓励按 3、1、4、2 逐项查表；不要直接代玩家提交 |
| 终检按钮不可提交 | “门卡当前到了哪一状态？出口面板的终检是否已经显式启动？” | 帮玩家辨认插纸、刷卡、启动终检是不同步骤，说明按钮已可见不代表提交条件满足 |
| 终检通过但未通关 | “终检完成后出口还显示什么动作？你是否已经释放门锁、推门并走出？” | 按公开出口状态提醒剩余门操作和最后移动 |
| 可选故事发现 | “你刚取走的物件原来放在哪里？通电后有没有多出新的可观察位置？” | 作为可选探索建议，明确不会阻断主线 |

建议把伙伴回复限定为“根据已知线索提出问题/下一步观察或操作建议”，不让它替玩家执行动作。每次应读取真实当前状态来选择未完成且当前可操作的目标，而不是固定催玩家进入下一房间；如果玩家靠猜测已完成柜锁或登录，即使没有发现全部推理线索，也不应再提示重做已完成目标。具体提示级别、触发条件、引用方式与模型输入需另行设计和审查；本文件不授权把后台真值或全文复制给模型。

## 历史版本提醒

旧版材料、测试或截图里可能出现 `4792`、`231` 等数字终检输入。它们不属于当前 v3.4.0 的终检流程；当前应通过源序、纸条和设备表推导四设备顺序并使用顺序提交。不要把旧版数字答案带入当前游玩说明或 AI 引导。

## 当前 UI 的物品选择操作

当前界面中，选中背包物品后点击一般物件会默认尝试对该目标使用道具；若要观察别的物件，先取消物品选择。已插纸的终检控制台及其四个设备按钮是本轮交互例外，不受门卡选中状态影响。终检通过后，在回到出口释放门锁前若门卡仍处于选中状态，先取消选择，再观察出口并使用出口自身的原生操作按钮；否则点击出口可能被解释为再次刷卡，让人误以为门锁无法释放。

这只是当前界面行为说明。背包选中状态属于 UI 暂态，不是后台 `visible_state` 字段，也不能据此认定 AI 已知玩家当前选中了什么。
