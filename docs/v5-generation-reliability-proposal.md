# v5 多房间生成可靠性修订提案

日期：2026-10-24。状态：**DRAFT，未纳入已接受计划，未实施**。本稿供选择生成方式；当前执行范围仍以 [v5构建计划](v5-build-plan.md) 为准。本文不授权付费调用，也不证明未来方案通过验收。

## 1. 为什么需要重新选择生成方式

第三轮在当前提示源码上真实调用G2两房间/normal、G3三房间/hard各一次，两份草稿均被原准入规则拒绝。不是输出截断或求解器容量问题：供应商均正常结束，输出710/1306 tokens，低于6000上限；草稿满足基本JSON形状，但不满足组合后的领域语义。

| 样本 | 实际第一拒绝 | 其他独立观察 |
| --- | --- | --- |
| G2 | 数字密码拼入设备字母，`INVALID_CODE` | 位置读取配方没有任何读取位置 |
| G3 | 只有5个谜题，应为6个，`PUZZLE_COUNT` | 资料未放入场景物件；映射没有源序；位置读取没有位置；困难关组合谜题数不足 |

当前提示已经明确数字密码、谜题数量、映射需要源序及困难关组合数。再增加文字可能有帮助，但没有证据表明能可靠消除这些跨字段错误。增加输出额度也不能解释本轮失败。原稿、拒绝结果和第一拒绝/后续静态观察分别保留，不能修改后重新标成原样本成功。

三轮真实生成分别是0/3、1/3、0/2，提示源码不同，不合并为当前成功率。伙伴第三轮首答与追问在历史真实G1的合法重建阶段均实际交付，说明资料标题修复有有限实际证据；不代表多房间生成或所有对话质量通过。

证据：[第三轮独立复核](../review/findings/v5-round3-real.md)、[原始结果](../evidence/upgrade/v5.0/real-samples-round3/result.json)。第三轮实际4次调用，usage保守费用上界增量0.0294056元；0.389912元是发送前预占上界，不是账单。全部名额已使用，不自动追加。

## 2. 两种方案及实际取舍

| 项目 | A：保留模型生成完整LevelDraft | B：程序确定关系骨架，模型生成内容与材料参数 |
| --- | --- | --- |
| 模型职责 | 自行设计房间、依赖、引用、物件和材料 | 主题、场景叙事、物件名称，以及有严格类型的数值、排列、映射参数 |
| 程序职责 | 原样解析并严格编译、证明、拒绝 | 先选定合法骨架和填参合同，再确定性构造Draft，仍严格编译、证明、拒绝 |
| 结构自由度 | 模型可自由选择白名单内的依赖和组合 | 限于已实现并验证的骨架族；由程序选择拓扑、跨房关系、物件槽位 |
| 多样性 | 较大，但目前有效输出不稳定 | 保留主题、谜面与答案参数变化；不能声称任意新结构或无限玩法 |
| 主要风险 | 模型继续违反全局约束，玩家频繁生成失败 | 骨架重复、叙事与材料不够贴合；参数不合格仍可能失败 |
| 费用与失败 | 一次调用，不自动重试 | 同样一次调用，不自动重试；不合格填参不修补、不替代 |
| 原计划影响 | 设计方向保持，仍需可靠性证据 | 改变“模型提交完整草稿”的内部合同与ADR，必须明确接受结构自由度下降 |

**建议选择B，前提是接受结构自由度的取舍。** 它把本轮反复出错的全局引用与配方连接交给可验证代码，同时让AI继续生成实际谜面参数；不是只替换故事文字。B不能冒充原方案的等价内部优化，也不能只凭本稿就开始实施。

若保留A，后续可离线补明确“每份资料恰有一个可发现物件”和“index合并位置非空”，并审查更窄的结构约束输入；这些都不能预填为已解决实际可靠性。下一次真实验证仍须新的来源绑定预检和有限授权，不连续用付费重试代替实现决策。

## 3. B具体如何工作（待选定后实施）

1. 程序根据房数、难度和服务端生成种子选择版本化的生产骨架。先确定房间顺序、谜题数、机制、引用、跨房资料、依赖和槽位。骨架不得引用后房才能取得的前置材料，也不得把必需物件锁在自身后面。
2. 为每个填参槽生成严格合同。槽名只对应本次已选骨架；模型不创建新的全局ID、依赖边、脚本或资源地址。未知字段、缺项、重复项、错误类型和超范围值直接拒绝。
3. 模型一次返回主题内容及真实谜面参数。例如：数字资料片段、源序值、合法位置排列、符号对应值、四设备的合法排列。每种参数分别规定长度、字符域、唯一性与允许值。不能把数字资料与设备资料交给模型任意混接。
4. 程序按事先声明的槽位规则构造完整LevelDraft。该步骤是合同定义的转换，不是收到坏草稿后补字段、改答案或修引用。任一填参不合格就终止该次生成，不拿默认值、测试fixture或历史关卡顶替。
5. 完整Draft继续通过现有严格引用/材料/依赖/布局检查、25000状态/5秒规划及真实规则witness回放。只有全部通过才进入现有Store提交链，失败仍是拒绝/未知，不能放行。
6. 原CompiledLevel、定义hash、会话、档案和公开状态继续作为执行权威。恢复使用保存的完整定义，不重新调用模型，不根据新蓝图重造旧档。模型内部输出合同的版本及来源需在验证记录中明确标注。

生产骨架必须是新的明确生产模块，不能调用当前仅用于教学/合成验证的`make_fixture`。首版骨架族的数量和选择规则需要写入更新后的规格；覆盖九种房数/难度并不等于九种以上结构，更不等于无限结构。

骨架必须逐项满足现有规模约束：谜题数为房数+难度偏移且最多6；多房有真实跨房材料或道具依赖；normal至少1个双资料谜题；hard至少2个且依赖深度至少3；每房物件不超过8、道具不超过4；保持四种机制和显式EXIT。程序生成的结构也必须经同一准入验证，不能享有绕过权限。

## 4. 保留什么，改变什么

| 范围 | 处理 |
| --- | --- |
| GEN-01主题/规模/难度 | 保留用户输入；B将结构设计自由收敛到骨架族，必须在正式规格和界面说明中如实表述 |
| GEN-02–04 | 保留严格拒绝、任务状态、无重发和求解上限，不放宽数量或材料充分性 |
| USER/KEY/COST | 保留账号归属、临时BYOK、固定供应商及单次6000/60、0.20元上限；不新增供应商、模型调用或费用豁免 |
| SAVE/SYNC/API | 目标是公开v2接口和完整Draft/规则执行格式不变，复用原事务和档案；如实现证明必须改版本，先单列兼容方案 |
| AI/UI/ASSET/LEGACY | 复用现有公开投影、伙伴、通用场景与登记素材，不改经典规则、旧库或原始素材 |
| ENG/EVAL | 为新模型合同和组装代码新增独立来源绑定证据；旧有限Claim和历史判读不冒充新路径验证 |

不新增编辑器、社区、云存档、联网部署、新机制、生图或自动重试。结构可解不等于叙事正确、有趣、难度符合真人时间；这些仍需有限实际样本及人类体验确认。不得据此称安全绝对、任意主题均可生成或课程所有判读已完成。
