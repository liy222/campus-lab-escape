# V5评价与观测：一张检查说明

本轮按章节03补齐必要评价与运行记录。当前主题为“雨夜里的天文社旧活动室，寻找封存的观测记录”。本说明复用已有API、浏览器检查与生成任务，不要求新平台或付费模型裁判。

2026-10-29更新：雨夜天文社已接入1.1.0手绘包（3背景、12物件/状态原图，场景与特写共源）；实际检查和限制见[当前阶段](../evidence/project/stages/v5-handpainted-rebuild/stage.json)。下表“初始状态”保留制定标准时的情况，不代表当前仍未制作；真人对画风/主题的一致性接受仍待发生。经典与V5现行界面和检查仅面向电脑鼠标/键盘，1280×720与1920×1080。

## 1. 主题一致性标准

这些标准用于下一阶段雨夜天文社资源包，亦用于区分本轮已完成的文本链路和仍待完成的体验。

| 编号 | 输入/场景 | 可观察预期 | 检查方式 | 初始状态 |
|---|---|---|---|---|
| THEME-01 | 原主题进入生成、保存、重登录继续 | 原主题可读；标题、故事、房间氛围确实围绕天文社和寻找观测记录 | 自动核对传递/展示；真实故事贴合度人工核条 | 链路已有旧证据，本轮新结果另列；真实创作质量待核 |
| THEME-02 | 打开主题场景 | 能看出夜晚与降雨情境，主要场景能识别为天文社活动/观测空间 | 看场景截图和实际画面，不只匹配文字关键词 | 专属场景未制作，未验收 |
| THEME-03 | 查看主要资料、道具、装置 | 观测记录、星图、望远镜等按实际谜题需要选用，身份合理；通用家具可复用 | 对照原主题、当前房间和物件列表人工核查 | 专属物件未制作，未验收 |
| THEME-04 | 从场景点击物件并改变设备状态 | 名称、外观、特写和状态相互对应；说明不要求游戏中不存在的操作 | 自动核对资源标识/实际交互；人工看整体对应 | 当前通用素材范围与专属包分别核查，不能相互冒充 |
| THEME-05 | 更换为目录未支持的主题 | 如实说明通用画面覆盖范围，不能声称任意主题已有专属美术 | 看创建说明、场景和资源目录；未来扩展时复核 | 当前仍使用通用手绘素材 |

不以“含有天文社几个字”、编译通过或自动到出口替代上面的主题体验判断。没有实际检查的项保持未核；图像尚未制作的项不填通过。

## 2. 技术检查约定

2026-10-29用户将当前与后续UI范围调整为桌面；旧结果和旧标准快照保持其历史来源，不作为本轮重新通过。

| 编号 | 情境 | 预期 | 实际记录应包含 |
|---|---|---|---|
| UI-CIRCUIT | 线路成功提交后 | 九模块及提交按钮禁用，光标不是wait/progress | 模块数量、每个disabled/cursor及提交按钮的实际值 |
| UI-PENDING | 动作请求在途、错误反馈返回后 | 在途aria-busy为true；返回后恢复false且可继续合法操作 | 实际aria-busy、错误码、返回后的可操作状态 |
| UI-LAYOUT | 1280×720、1920×1080（自2026-10-29起的桌面标准） | 可用控件宽高均至少44 CSS像素；无横向溢出；面板可滚动 | 实际viewport、最小宽高、scrollWidth/clientWidth、面板高度和overflow |
| DATA-RESTORE | 保存、推进、选择恢复；重登录 | 原关卡和正确早期公开状态恢复；原主题仍可读 | 恢复前后必要公开计数、HTTP状态及主题匹配结果，不输出完整状态 |
| OBS-GENERATION | 两个不同输入或不同失败分支 | 记录反映实际阶段/数量变化；同一job_id可串起一次生成 | UTC时间、源码指纹、请求规模、安全实际计数、受控阶段/原因和最终状态 |
| CHECKER-SELF | 隔离提供wait光标、过小控件和已知正常值 | 错误样例判失败，正常样例判通过 | 自测的预期、实际和判定；明确非真实页面观测 |

阈值与规则事先确定，不为拿到通过而修改预期或删除失败项。Synthetic输入下实际执行API和浏览器动作属于工程测试；Synthetic模型文案不代表真实AI质量。

## 3. 运行与查看

浏览器沿用既有入口，默认读取固定索引中的当前阶段，并创建一个全新结果目录：

```powershell
& node tests/v5/run_experience_browser.mjs
```

默认位置为`evidence/project/stages/<当前阶段>/automated/browser-<UTC>-<run-id>/`；索引缺失或无效时明确未运行，不猜阶段。也可用`--output`显式指定新目录。该入口使用隔离Synthetic服务/账户，不操作玩家的8001服务或数据库。每轮结果保存run_id、起止UTC时间、源码版本/必要文件指纹及实际加载的前端产物标识。新目录不能覆盖旧输出。程序未能运行时看失败记录，不将计划写成通过。

生成任务的内部观测只供本机开发者按任务ID读取：

```powershell
& 'C:\Users\liyh\.conda\envs\1\python.exe' -B -X utf8 -m scripts.generation_trace --job-id '<界面中已有的任务ID>' --export 'evidence/project/stages/2026-10-28-evaluation-observability/logs/<新文件名>.json'
```

隔离验证可显式使用`--database <TEMP目录>/game-v5.sqlite`。入口只读，不启动应用，不迁移数据库，不读取关卡私有定义或令牌。没有采集过事件的旧任务应明确显示未记录，不用当前状态补写一段历史。

内部事件来自真实处理分支，保留必要阶段、时间、源码指纹、请求规模/计数和受控原因。公开API的错误码保持原约定。主题原文、密码、Key、Cookie、模型正文、答案与完整私有定义不进入这些记录。

`source_version`标明观测记录格式；`git_revision`和文件指纹用于识别采集时的磁盘源码。它们需与实际执行入口及Synthetic注入说明一同阅读，不能单凭一个版本标签推断运行对象或真实模型质量。

## 6. 持续保存、历史归档与真人记录

固定根为`evidence/project/`。开发中每次真实检查、失败、修复和反馈及时保存；大阶段结束集中交付。`index.json`指向当前阶段，`stages/<stage>/`分自动结果、日志、标准/评价、技术复核和图片。

```powershell
# 新大阶段开始时初始化；不是验收
& 'C:\Users\liyh\.conda\envs\1\python.exe' -B -X utf8 -m scripts.evidence_hub init --stage '<新阶段英文标识>' --title '<阶段名称>' --activate
# 已有安全文件原字节归档，源文件保留，禁止覆盖
& 'C:\Users\liyh\.conda\envs\1\python.exe' -B -X utf8 -m scripts.evidence_hub collect --stage '<阶段标识>' --category automated --source '<实际结果文件>'
```

旧证据可迁移归档，保留原执行日期、来源、原内容和实际状态；复制时记录导入时间与来源，不当新执行。固定路径被可信登记/历史清单引用的原件暂留兼容。[历史索引](../evidence/project/HISTORY.md)列出已归档的代表性V5结果与更早原入口；未声称搬完全部历史文件。

真人材料独立放在`human-reviews/<stage>/round-XX/`：原话和来源追加到events.jsonl，review.md供阅读，用户提供的原截图保存到screenshots/。只有真实反馈才调用record-review；自动化截图留在阶段自动结果中。本人、真实同伴与AI技术检查分别记录。

2026-10-30用户补充：真人反馈成功但未附图时，提交可复用匹配阶段的既有自动截图。原图留在stages/<stage>/automated/，在人类反馈目录用链接和来源清单关联，注明自动Synthetic、原运行时点和非本人截图。本人结论仍来自实际原话，不以辅助图替代；不把复用记为新测试或自动生成真人截图。

每个大阶段结束必须明确邀请本人看效果，给出入口、三至五项重点与未决问题，等真实反馈后再记录结论。需要修复时继续同一阶段的新核验轮，旧反馈/截图保留。没有收到真人核验时保持未核，不能由“继续”、技术通过或图片导入自动填写接受。
