# 默认提示与当前解谜流程核对（2026-10-18）

结论：现有18条分级提示的事实内容符合当前解法，没有发现旧版数字终检答案、错误设备对应或把未发现线索作为提示引用。但它们只覆盖4类谜题关系，不能作为完整流程引导；默认选题存在固定优先级，通用无提示文案也不能准确解释设备未就绪。

## 发现

1. **默认主题固定优先，重复请求不会自然轮换。** Mock总取topics[0]。柜码同时满足两个主题时总取sample_time；登录同时满足两个主题时总取login_identity。sample_mark/login_time在第一主题缺条件时仍可达，不能说它们永远不会出现。主题资格随状态改变，但同一资格集合下没有提问分析、记忆或轮换。出处：hints.py的available_topics和run_hint。
2. **玩家写的问题不影响当前提示选择。** 界面要求输入“想获得什么提示”，但当前v3.4分支没有使用start.message/start.history；即使具体问密码格式，默认仍可能提示用户名。真实provider分支也只接收主题名和已发现线索ID，最终文字仍由同一模板渲染。本轮未调用真实provider。
3. **关键操作阶段没有对应提示。** 未覆盖玻片获取/安装/再次观察；柜码已接受但还未开柜；拿保险丝、开箱/移护板/安装；线路通过但尚未合闸；电脑启动/继续启动/登录后读取；拿纸条和门卡；插纸/刷卡/启动终检；终检后释放锁、推门、走出。缺少任一必需线索时，也不会针对缺口引导观察。可选故事没有提示，但它不是通关阻塞，优先级较低。
4. **“信息不足”的回退有时归因不准确。** NO_HINT固定说“目前已发现的信息还不足以形成提示……取得更多线索后再询问”。实际上柜锁已接受、线路CIRCUIT_READY、电脑已UNLOCKED、出口CARD_ACCEPTED或终检已完成等真实状态也无主题，卡点是操作/就绪状态而非知识不足。R3即便源序、纸条、设备表都已知，插纸或刷卡后只要没进入FINAL_CHECK，就没有sequence主题。

以上是对当前覆盖能力/交互预期的发现，不表示它违背了旧版“仅已知线索、限制泄题”的设计。也不建议把全部下一步直接展示给玩家；如后续授权改进，应在请求提示时按公开设备状态选择适量的观察/推理/就绪提醒。
